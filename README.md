# Archive

Десктопний застосунок для обліку управлінської документації та судових справ. Інтерфейс українською мовою, Flutter-клієнт і Serverpod 4.0.4. Поточний запуск налаштований на нативне вікно macOS.

## Можливості

- Файли справ: ручне додавання, відкриття, збереження, видалення та відновлення.
- Картки справ із полями для учасників, судових інстанцій, виконання рішення, архівного зберігання та фізичного розташування.
- Сторінки по 50 справ із вибіркою з Drift; пошук і фільтри застосовуються до всього архіву, експорт охоплює всі знайдені справи.
- Короткий статус справа вгорі показує поточну дію або час останнього оновлення.
- Збереження однієї справи оновлює її локальну копію без повторного завантаження всього архіву.
- Імпорт Excel з вибором аркуша, зіставленням колонок, перевіркою та попереднім переглядом.
- Номенклатури у Word, окремі описи справ тривалого та постійного зберігання з експортом в Excel.
- Вхід за логіном і паролем, реєстрація без пошти та адміністративна панель доступу.
- Адреса сервера в локальних налаштуваннях застосунку, доступних до та після входу.
- Локальна копія доступних справ для перегляду без зв’язку. Додавати, імпортувати, редагувати й змінювати права без сервера неможливо.

## Запуск

Залежності встановлюються через `flutter pub get` у `archive_flutter`. Для доданого модуля авторизації локальні секрети можна підготувати один раз командою `python3 tool/configure_local_auth.py` з кореня проєкту. Скрипт не замінює наявних значень і не друкує секретів.

Запустіть `serverpod start` у `archive_server`. Runner генерує клієнт і серверні моделі, стежить за змінами та запускає нативний Archive через конфігурацію `desktop`, `device: macos`. Веббраузер для застосунку не потрібний. Міграції застосовуються через Serverpod MCP або пункт міграцій у runner.

Наявні акаунти перенесено на логіни без зміни їхніх паролів, ідентифікаторів і прав. Для унікальних коректних адрес логін — частина пошти до `@` малими літерами; у разі збігів використовується `user-<id>`. Нові користувачі реєструються за логіном і паролем та очікують видачі прав адміністратором. Пошта й коди підтвердження не потрібні. У новому розгортанні початкового адміністратора призначає оператор сервера; обраний користувачем логін ніколи не надає адміністративних прав автоматично.

Логін містить 3–64 символи: латинські літери, цифри, крапку, дефіс або підкреслення. Регістр не має значення. Пароль — 8–256 символів. Сеанс зберігається в захищеному сховищі ОС. Перевірку паролів, захист від перебору та JWT забезпечує Serverpod. Внутрішній адаптер облікових даних не надсилає листів.

Власний пароль змінюється кнопкою ключа біля облікового запису. Якщо пароль забуто, адміністратор скидає його в «Користувачі та доступ» і передає тимчасовий пароль користувачу. Після входу той обов’язково створює власний пароль. Старі токени відкликаються; паролі не потрапляють до журналу аудиту. Офлайн-копію можна очистити після скидання лише при наступному підключенні пристрою до сервера.

## Адреса сервера

Відкрийте «Налаштування» на екрані входу або внизу лівого меню. Вкажіть повну адресу API, наприклад `http://192.168.0.102:8080/` у локальній мережі або `https://api.example.com/`. На Windows потрібно вказати адресу комп’ютера із Serverpod; `localhost` означає сам Windows-комп’ютер.

Адреса зберігається на цьому пристрої між запусками, без перебудови застосунку. Зберегти її можна й без зв’язку. Зміна адреси завершує локальний сеанс, очищує його кеш та відкриває екран входу на новий сервер. Повторне збереження тієї самої адреси не завершує сеанс. Серверні записи й файли залишаються на своєму сервері. Токени входу зберігаються окремо для кожної адреси в захищеному сховищі ОС; URL у `archive_settings.json` не містить токенів чи паролів. До першої зміни використовується адреса збірки `SERVER_URL` або `assets/config.json`.

## Тема оформлення

У «Налаштування» виберіть тему — «Системна», «Світла» або «Темна» — та натисніть «Зберегти». Системна тема автоматично реагує на оформлення ОС. Вибір зберігається на пристрої, працює без сервера та не завершує сеанс. Обидві теми охоплюють картки, учасників, файли, імпорт, форми, помилки й адміністративні екрани.

## Імпорт даних

1. Оберіть модуль і перетягніть одразу кілька `.xlsx` у вікно імпорту або додайте їх кнопкою. Перший рядок кожного файлу — назви колонок.
2. Для кожного файлу оберіть аркуш. Поля згруповано за розділами картки. Навпроти поля застосунку виберіть колонку Excel. Роль учасника та його ім’я налаштовуються окремо, номер провадження береться з того самого рядка.
3. Перевірка автоматична. Зверху показано кількість файлів, записів, нових і наявних справ, об’єднань, непризначених колонок, пропущених рядків і помилок. Непризначені колонки не імпортуються; рядки без номера справи пропускаються без блокування решти імпорту.
4. Номер справи обов’язковий і повністю визначає унікальність судової картки. Учасники зберігаються разом із роллю та номером провадження; одна справа може містити багато проваджень. Управлінська картка визначається індексом та роком номенклатури.
5. За замовчуванням заповнюються порожні поля наявних справ. Можна обрати заміну значень новими. Порожні клітинки не стирають наявні значення, учасники об’єднуються без повторів. Порядок файлів визначає порядок доповнення.
6. Загального обмеження кількості записів немає. Фонове опрацювання, передача порціями, скасування, ідемпотентний запис та фінальна транзакція запобігають частковому імпорту. Підсумок містить лише загальну статистику.

Невідповідність порядку дат показується окремим лічильником зауважень і не блокує імпорт. Дати зберігаються як у джерелі; некоректні календарні дати залишаються помилками.

Дати: `ДД.ММ.РРРР` або `РРРР-ММ-ДД`; числові дати Excel підтримують календарі 1900 і 1904. Формули потрібно замінити значеннями. Експорт зберігає зв’язки учасника, ролі та провадження в окремих колонках.

## Файли справи

У збереженій картці справа є окрема світло-сіра панель «Файли» зі своїм прокручуванням. Кнопка «+» дозволяє додати кілька файлів; біля кожного є відкриття, збереження та, для редактора, видалення. Нову справу спочатку потрібно зберегти. Основна інформація зберігає звичне оформлення з послідовними розділами.

Вміст зберігається в базі Serverpod і передається частинами по 256 КіБ, без загального обмеження розміру файлу на рівні застосунку. Незавершені завантаження не відображаються. Файли успадковують права справи, зберігаються при її об’єднанні, а додавання, видалення та відновлення потрапляють у журнал аудиту. Видалений файл можна повернути через повідомлення або журнал.

Доступні файли автоматично завантажуються у локальну Drift-базу, тому після завершення синхронізації їх можна відкривати та зберігати без сервера. Частини зберігаються окремо від знімка карток. Після відкликання прав локальні файли прибираються при наступному підключенні; вихід очищує кеш цього облікового запису. Документи й зображення відкриваються стандартною програмою ОС; інші типи можна зберегти на диск.

## Видалення та аудит

Справи й номенклатури можна видаляти з підтвердженням та відновлювати одразу через повідомлення. Адміністратору доступний «Журнал аудиту»: автор, час, дія, значення до/після та джерела імпорту. Через подію видалення можна відновити запис пізніше. Оригінали об’єднаних старих карток зберігаються прихованими.

Строки, вид зберігання, дата можливого знищення та позначка внесення до опису наразі заповнюються вручну. Автоматичні правила за категоріями справ не ввімкнені.

## Автономний режим

Після успішної синхронізації картки доступні з локальної копії для того самого облікового запису та сервера. За відсутності зв’язку відображається статус «Без з’єднання». Перевірка зв’язку повторюється кожні 30 секунд, також є ручне оновлення.

Локальна копія зберігається у SQLite через ORM Drift (`archive_local.sqlite` у каталозі підтримки застосунку). У транзакції оновлюються таблиці справ, номенклатур і вмісту документів, профілю та, для адміністратора, користувачів і журналу аудиту. Документи завантажуються завчасно, відкривати їх онлайн перед автономною роботою не потрібно. Старий JSON-кеш автоматично переноситься в Drift. Вихід видаляє локальні дані цього акаунта, відкликані права прибирають відповідні дані після підключення. Сеанс входу зберігається окремо в захищеному сховищі ОС.

## Оновлення Windows

Windows x64 має перевірку нових версій через налаштований Serverpod, завантаження й встановлення підписаних оновлень із налаштувань. Рекомендований випуск — GitHub Actions → Windows installer → Run workflow: номер збірки, установщик, підпис і GitHub Release готуються автоматично, а сервер забирає готовий пакет кожні 5 хвилин. Один раз потрібно додати ключ у Actions secret `ARCHIVE_UPDATE_PRIVATE_KEY`. Установщик Inno Setup збирається командою `tool/build_windows.ps1` на Windows; налаштування, вхід і Drift зберігаються. Ключ підпису не публікується разом із випуском. Інструкція збірки, публікації й перевірки: [docs/windows-releases.md](docs/windows-releases.md). Оновлення macOS поки не реалізовані.

## Перевірки

- `dart analyze` з кореня проєкту.
- `dart test` у `archive_shared`.
- `flutter test` у `archive_flutter`.
- `dart test` у `archive_server`. Тести використовують окремий вбудований PostgreSQL без Docker і не працюють із робочими даними.

## Структура

- `archive_shared` — поля та правила перевірки.
- `archive_server` — авторизація, права доступу, зберігання та журнал змін.
- `archive_client` — клієнт, що генерується Serverpod.
- `archive_flutter` — інтерфейс, імпорт/експорт і локальний кеш.
